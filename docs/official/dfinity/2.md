To build a DEX trading pair with ICP, you will interact with ICP and the paired token using the **ICRC-1** and **ICRC-2** standards [[ICRC-1: Fungible tokens](https://docs.internetcomputer.org/references/digital-asset-standards/#icrc-1-fungible-tokens); [ICRC Token Ledgers](https://skills.internetcomputer.org/skills/icrc-ledger/)]. 

Here is the essential data and information you need to query and save for the tokens in your trading pair:

---

### 1. Token Identification & Metadata to Store

For each token (including ICP), you should query and store the following ledger metadata [[ICRC-1: Fungible tokens](https://docs.internetcomputer.org/references/digital-asset-standards/#icrc-1-fungible-tokens); [ICRC1 Interface](https://github.com/Web3NL/motoko-book/blob/main/src/internet-computer-standards/icrc1.md)]:

- **Ledger Canister ID:** The principal ID of the token's ledger canister (e.g., ICP ledger is `ryjl3-tyaaa-aaaaa-aaaba-cai`) [[ICP ledger](https://docs.internetcomputer.org/references/system-canisters/#icp-ledger); [Well-known ledgers](https://docs.internetcomputer.org/guides/digital-assets/ledgers/)].
- **Index Canister ID (Optional):** Used for indexing per-account transaction history (e.g., ICP Index is `qhbym-qaaaa-aaaaa-aaafq-cai`) [[ICRC Token Ledgers](https://skills.internetcomputer.org/skills/icrc-ledger/)].
- **Token Name (`icrc1_name`):** e.g., `"Internet Computer"`.
- **Token Symbol (`icrc1_symbol`):** e.g., `"ICP"`.
- **Decimals (`icrc1_decimals`):** The decimal precision (ICP has `8` decimals). Always query decimals at runtime rather than hardcoding [[ICRC-1: Fungible tokens](https://docs.internetcomputer.org/references/digital-asset-standards/#icrc-1-fungible-tokens); [Well-known ledgers](https://docs.internetcomputer.org/guides/digital-assets/ledgers/)].
- **Transfer Fee (`icrc1_fee`):** Denominated in the token's smallest unit (e.g., e8s for ICP). Always query this at runtime because ledger transfer fees can change [[ICRC Token Ledgers](https://skills.internetcomputer.org/skills/icrc-ledger/); [Well-known ledgers](https://docs.internetcomputer.org/guides/digital-assets/ledgers/)].
- **Supported Standards (`icrc1_supported_standards`):** Verify whether the ledger supports standards such as `ICRC-1`, `ICRC-2`, etc. [[ICRC-1: Fungible tokens](https://docs.internetcomputer.org/references/digital-asset-standards/#icrc-1-fungible-tokens)].

---

### 2. Account Identification Model

To identify user and DEX deposit accounts, ICRC-1 uses a composite account model [[ICRC-1: Fungible tokens](https://docs.internetcomputer.org/references/digital-asset-standards/#account-model)]:

```candid
type Account = record {
  owner : principal;
  subaccount : opt blob;
};
```
- **`owner`:** The principal of the user or canister.
- **`subaccount`:** An optional 32-byte blob (defaults to all zeros if omitted). You can use distinct subaccounts on your DEX canister to manage individual user deposits or isolated pools [[ICRC-1: Fungible tokens](https://docs.internetcomputer.org/references/digital-asset-standards/#account-model)].

---

### 3. Core Token Operations for DEX Trading

To execute trades, deposits, and withdrawals, your DEX will interact with the following methods on the token ledgers [[ICRC-1: Fungible tokens](https://docs.internetcomputer.org/references/digital-asset-standards/#core-methods); [ICP ledger](https://docs.internetcomputer.org/references/system-canisters/#icp-ledger)]:

- **Checking Balances:** `icrc1_balance_of(Account) -> (nat)`
- **Transfers (Withdrawals / Payouts):** `icrc1_transfer(TransferArg) -> (variant { Ok : nat; Err : TransferError })`
- **Allowances / Deposits (ICRC-2):**
  - `icrc2_approve`: The user approves the DEX canister to spend a specific token amount [[ICP ledger](https://docs.internetcomputer.org/references/system-canisters/#icp-ledger)].
  - `icrc2_transfer_from`: The DEX canister pulls the tokens from the user's account to fund an order or liquidity pool [[ICP ledger](https://docs.internetcomputer.org/references/system-canisters/#icp-ledger)].

---

### 4. Important Transaction Parameters

When constructing transfers on the ledger, always handle [[ICRC-1: Fungible tokens](https://docs.internetcomputer.org/references/digital-asset-standards/#transfer-arguments)]:
- **`created_at_time` (nat64):** Include this timestamp to enable transfer deduplication. Ledgers reject identical duplicate transfers submitted within a 24-hour window [[ICRC-1: Fungible tokens](https://docs.internetcomputer.org/references/digital-asset-standards/#transfer-arguments)].
- **`fee` (nat):** Ensure sufficient balance covers both the transfer amount and the current `icrc1_fee` [[ICRC-1: Fungible tokens](https://docs.internetcomputer.org/references/digital-asset-standards/#transfer-arguments); [ICRC Token Ledgers](https://skills.internetcomputer.org/skills/icrc-ledger/)].
