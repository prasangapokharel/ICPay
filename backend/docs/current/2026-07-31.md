## Open risk: plaintext controller

The mainnet canister's controller is the dfx `default` identity, whose private
key is **unencrypted on disk**. It custodies real user ICP and can be upgraded
by anyone with filesystem access. Rotate before real users:

```
dfx identity new secure --storage-mode password-protected
dfx canister update-settings icp_wallet_backend \
  --add-controller <new> --remove-controller <old> --network ic
```

No redeploy needed. Flagged repeatedly; still outstanding.

## Bugs found and fixed this session

**1. Upgrades wiped all user data (critical).** `main.mo` declared storage as
`transient` inside a `persistent actor`. `transient` opts *out* of orthogonal
persistence, so every upgrade destroyed every user, balance record and
transaction. Proved it: created a user, upgraded, `getUser` → `(null)`. Removed
`transient` from the five storage bindings; services stay transient since they
are just reference records rebuilt on upgrade. Re-verified state now survives.

**2. "User not found" on withdraw while balance displayed.** `actor.login()`
(which *creates* the user record) ran only on connect. On later page loads the
provider restored the cached delegation and called `getUser()` — a read-only
query that creates nothing. After bug #1 wiped the canister, the browser kept a
valid delegation, so the UI looked signed in against a canister with no record.
Balance still rendered because it reads the **ledger** (funds live in a
principal-derived subaccount, independent of the user map) while withdraw needs
the **user record**. Fix: session restore calls `login()` (idempotent) instead
of `getUser()`.

**3. Recipients saw no incoming transaction.** `doTransfer` wrote exactly one
row tagged with the *sender's* `userId`; `getByUser` filters on that field, so
the recipient's history was genuinely empty. Now resolves whether the
destination belongs to a local user (by subaccount for ICRC-1, by account
identifier for the hex path) and writes them a matching row.

> The recipient row is typed `#deposit`, **not** `#transfer`. `syncDeposits`
> credits `ledgerBalance − totalDeposits`; with `#transfer` the arrived funds
> would look unaccounted for and be credited a **second time**. Verified:
> after a transfer, `syncDeposits` returns "No new deposits found" and the
> balance holds. Self-transfers are guarded against phantom rows.

**4. id.ai could not be reached from localhost.** `getIsLocal()` forced host,
canister *and* identity provider to local, so "Connect Wallet" never left the
replica. Added `NEXT_PUBLIC_IC_NETWORK=ic` which flips all three together.
All three derive from one value — they must never drift (see below).

## The delegation constraint (do not re-break)

A delegation signed by mainnet Internet Identity (`id.ai`) **cannot** be
verified by a local replica — different root key. It surfaces as:

```
Invalid delegation: Invalid canister signature ...
Invalid combined threshold signature
```

This is protocol-level and unpatchable. I caused this outage myself by creating
`.env.local` with `NEXT_PUBLIC_II_URL=https://id.ai` while pointed at the local
replica, after having already warned about it. Host, canister and identity
provider must always name the **same** network.

So: **id.ai cannot be tested locally.** Local testing uses the local II
canister; id.ai is exercised only against a deployed canister. `auth-provider`
also self-heals — a stored delegation that fails its probe is discarded and the
user signed out, instead of surfacing an opaque 400.

**No real ICP is needed for testing.** Local minted test ICP covers deposit,
sync, transfer, withdraw and fees. Mint with `dfx --identity minter` — legacy
`transfer` and `icrc1_transfer` reach the same account (verified: both views
returned 24,991,000 for one account), so either form works.

## Scale limit — measured, not estimated

`getDashboard` calls four helpers that **each iterate every transaction in the
canister**, not just the caller's. Cost therefore grows with everyone's
combined history.

| Measurement (local replica, 503 txs) | Result |
|---|---|
| `login` (no tx scan) | 7.2M cycles |
| `getDashboard` before single-pass fix | 70.2M cycles |
| `getDashboard` after single-pass fix | 55.3M cycles |
| Cost of one full-list scan | ~7.5M cycles |
| Inter-canister `icrc1_balance_of` | ~40.6M cycles |
| Latency 100 → 500 txs | 1.84s → 1.85s (network, not compute) |

**The dominant cost is the ledger call, not the scans.** Decomposing the 48.1M
of overhead that remains above the `login` baseline: ~7.5M is the single
remaining scan, ~40.6M is the inter-canister `icrc1_balance_of` in
`DashboardService.mo`. The scans only overtake the fixed ledger cost past
~5,400 rows.

**The binding constraint is running out of cycles, not trapping.** At 100 users
× 5 loads/day (2,000 rows) the canister burns ~122B cycles/day against 833.2B
usable — dead in under a week with a full balance. The per-message instruction
trap sits at ~128,000 rows, roughly 60× further out than the funding limit.
An earlier version of this doc said 100k rows ≈ "14.1 trillion cycles"; the
arithmetic gives 14.1 **billion**, and the "~20–30k rows / 1,000–1,500 users"
ceiling derived from it was wrong.

Mitigated this session: `getByUser` and `getRecentByUser` walk `reverseValues()`
newest-first and stop once the page is filled, page size is clamped to
`MAX_PAGE_SIZE = 50` (verified: requested 500 → served 50 of 503), and the three
`getTotal*` aggregates in `getDashboard` were collapsed into a single
`getUserTotals` pass — 70.2M → 55.3M, **−21.3%**. Frontend `useDashboard` also
gained `dedupingInterval: 30_000`, since an unthrottled `revalidateOnFocus`
fired a full-cost update on every tab refocus.

**Real fix, in priority order:**

1. **Make `getDashboard` a `query`.** `icrc1_balance_of` is itself declared
   `shared query` (`LedgerClient.mo:5`), so the frontend can call the ledger
   directly and the backend read becomes free. This removes ~100% of the read
   path and is worth more than everything below combined. Cost: the displayed
   balance is served by one node and is no longer consensus-backed. Transfers
   and withdrawals stay updates, so funds cannot move on a forged number.
   Composite query is **not** an option — composite queries cannot cross
   subnets and the ICP ledger is on the NNS subnet.
2. A per-user index (`Map<UserId, List<Transaction>>`) plus running totals
   updated on write. Note this only reaches ~48M/call while the ledger call
   remains in the path, so it is much less valuable than (1) and should follow it.
3. `recipientOf` scans all users linearly per transfer — wants a
   subaccount→user index at scale.


## Cycle-saving audit (`docs/canister/canister.md`)

Applied the doc's #1 rule: `getTransactions` and `getTransactionDetail` were
update calls despite being pure reads — converted to `query`. These are the
highest-traffic endpoints. The rest of the doc's advice was already followed:
no heartbeats, no HTTP outcalls, `Map`/`List` structures, minimal stored state.

## Frontend state

Mobile-first, phone-width column, shadcn/ui over **Base UI** primitives.

> Base UI uses `render={<Element />}`, **not** `asChild`. `Menu.GroupLabel`
> requires a `Menu.Group` ancestor — omitting it throws
> `MenuGroupContext is missing` at runtime.

- **Header** — DiceBear `adventurer` avatar (seeded by principal) at left,
  theme toggle at right. Mount guard prevents a wrong-icon flash, since
  `resolvedTheme` is undefined until next-themes reads localStorage.
- **Balance card** — ICP logo straddling the top edge, amount, USD value. No
  24h % badge (removed on request). Card cannot use `overflow-hidden` or it
  clips the logo; the decorative layer is masked separately.
- **Bottom nav** — glass morphism (`.liquid-glass-strong` in `globals.css`,
  supplied verbatim by the user, plus dark-mode overrides for shadow and inset
  border). The raised center button is a **sibling**, not a child, because the
  glass class sets `overflow: hidden` and was clipping it. Uses
  `/images/navballcenter/1.png`.
- **Transactions** — accordion rows (the old table scrolled horizontally and
  cut off columns on mobile). Avatar, counterparty, `type · time`, inline memo
  with a message icon; expands to full addresses, fee, status, block link.
  No type icons anywhere — `getTxTypeIcon` was deleted.
- **Send Success** screen on both transfer and withdraw, replacing toasts.
- **SWR** across all pages via `hooks/use-wallet-data.ts`. Cache keys include
  the principal so switching identity cannot serve the previous user's balance.
  Deposit addresses are derived and never change → cached for the session.
  Fund-moving actions call `useRefreshWallet()`. Logout clears the whole SWR
  cache (it is module-global and would otherwise outlive the identity) and
  redirects to `/login`.

The ICP Dashboard link **does** work with a block index — it 302s to the hash
form (`/transaction/3d5b5a80…?index=37649279`). An earlier warning that it was
broken was wrong.

## Working agreements

- **Do not run large call loops** — they burn real cycles. Cap test loops at
  ~10–30 calls.
- Conserve tokens; do not read unnecessary files. Search symbols over full
  file reads.
- Return only changed files, minimal diffs, preserve formatting.
- Never stream full logs — `| tail -N`, surface errors only. Report
  `EXIT=${PIPESTATUS[0]}`; `... | tail -N && echo OK` masks failures.
- Use `./node_modules/.bin/tsc --noEmit` from `frontend/` (bare `npx tsc`
  fetches the wrong package).
- Never store private keys, seed phrases or passwords. Auth is Internet
  Identity only. Do not violate API→Service→Repository→Storage layering. Use
  only official ICP Ledger interfaces.
