IMPACT:
-------
1. Cycle waste - controllers still pay for canister storage (0 cycles/sec but
   still allocated)
2. Attack surface - controllers could reinstall malicious code into empty canisters
3. Confusion - users may encounter non-functional endpoints
4. Resource misallocation - cycles stored in empty canisters could be reclaimed
5. Potential for canister ID squatting or future abuse

SECURITY CONCERN:
-----------------
Empty stopped canisters represent dormant attack vectors. If a controller
reinstalls code into these canisters, they could be used for phishing, malicious
redirects, or as staging points for future attacks. Users checking these canister
IDs would see them as non-functional, potentially missing red flags.

FIX:
----
1. Controllers should either install proper WASM or destroy the canister
2. Use `dfx canister delete <canister_id> --network ic` to reclaim cycles
3. Publish canister status (active/stopped) on project documentation
4. Set up monitoring alerts for canister stop events
